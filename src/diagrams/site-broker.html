The AI agent runs in its own VM with the internet off. Inside, OPENAI_API_KEY is only a placeholder, and the agent calls http://openai.broker.koala.internal/v1. The request leaves the VM to koala-net, which passes it to koala-broker over the VM's private channel. The broker has no listening port. The broker checks the policy: the allowed requests, the allowed models and the limits. Allowed: the broker adds the real key from the key store on the way out only, and sends the request over TLS. The response comes back; the key never travels toward the VM. Not allowed (another path or model): refused with 403. It never reaches the service. A compromised agent can use only the access you granted, within your limits; it can't steal the key.

  1. An AI agent runs in its own VM with the internet off. Inside the VM, OPENAI_API_KEY is only a placeholder, and the agent calls http://openai.broker.koala.internal/v1; plain HTTP is fine because the traffic stays on the host.
  2. The request leaves the VM to koala-net, the VM's network helper on the host, which passes it to koala-broker over the VM's private channel. The broker has no listening port.
  3. The broker checks the policy: the allowed requests, such as chat completions and the model list; the allowed models, such as gpt-4.1-mini; and limits.
  4. An allowed request gets the real key from the key store (the login Keychain on a Mac, encrypted files on Linux) on the way out only, and goes to api.openai.com over TLS. The response comes back to the agent. The key never travels toward the VM.
  5. A request for another path or model is refused with 403 and never reaches the service.
  6. A compromised agent can use only the access you granted, within your limits; it can't steal the key.
