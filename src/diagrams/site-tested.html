Koala is tested by attacking it. Root in the guest attacks the boundary, fuzzers hit every parser of guest data, and crash checks kill the manager, VM processes and helpers at chosen moments.

  1. A Koala VM inside its boundary; sandboxed around it on the host: the VM's process, the network helper koala-net and the broker koala-broker.
  2. Root inside the guest attacks the guest channels (lengths, credits, order), the network (spoofing, fragments, floods under resource limits), storage and credentials. Each is refused at the boundary; a control VM beside it keeps working. On Linux, an escape probe under each production sandbox has every attempt refused.
  3. More than 40 fuzz targets in Swift, Go and C hit every parser of guest data, each with at least 100,000 generated inputs; the Swift and C ones run under AddressSanitizer.
  4. About 1,400 crash checks on each platform kill the manager, each VM's process and every helper (image extractor, file transfer, network helper, broker) at chosen moments. Each case checks that nothing is lost or left behind and that the VM starts again.
  5. A canary key is hunted through the VM's disk, its volumes and the image: not found there. It appears only on the upstream request to the API service, outside the VM.
  6. The same suites run on a Mac and on Linux, and on every release.
